# 不考虑历史兼容

对当前工作区的任何修改，一律**不需要考虑向后兼容**。

## 规则

1. **不做兼容层**：不为旧 API、旧数据结构、旧配置项保留适配代码、别名、shim、deprecated 包装。
2. **直接改调用方**：签名、接口、字段、命名需要调整时，直接修改全部调用点，而不是新增一个"兼容版本"。
3. **不留废弃代码**：旧实现能被完全替换时直接删除，不注释保留、不加 `@deprecated`、不加版本判断分支。
4. **不加降级/兜底分支**：不为"旧版本可能没有某字段"写 `?? 默认值`、`if (old)` 之类的防御代码。
5. **数据迁移一次性解决**：格式变更直接写一次性覆盖逻辑，不做新旧格式双向读写。
6. **优先最简方案**：在"兼容旧行为"和"更干净的新行为"之间，一律选择后者，并在回复中说明行为发生了什么变化。

## 例外

- 外部第三方契约（公开 API、他人依赖的包、平台强制的协议格式）不在本规则范围，需按契约执行。
- 用户明确要求保留兼容时，以用户要求为准。
